# 知识检索

OpenKB 根据请求的技术栈、项目和文件路径，从有效知识中选择上下文。所有匹配条目都应返回。不再根据任务关键词评分，也没有逐条配置的返回策略。

## 1. 选择知识适用范围

知识编辑器提供两种选择：

| 适用范围                              | 规则                                     | 示例                                               |
| ------------------------------------- | ---------------------------------------- | -------------------------------------------------- |
| **Global（全局）**                    | 不要求技术栈，请求未声明技术栈时也适用。 | 跨项目共享的 anti-slop 写作规则。                  |
| **Technology-specific（技术栈专用）** | 请求声明的技术栈必须包含所有选中的技术。 | 同时选中 CodeIgniter 4 和 PHP 时，两者都必须匹配。 |

依赖特定框架的知识应选择该框架。只选 PHP 也会匹配 Laravel 项目；只选 TypeScript 也会匹配不使用 Vue 的项目。框架主版本不同则不匹配，例如 Vue 2 不匹配 Vue 3。

项目和路径字段可为两种选择附加限制：

- **Project slug（项目标识）：** 请求必须指定同一项目。请求没有项目时，不返回项目专用知识。
- **Path patterns（路径模式）：** 至少一个请求文件匹配至少一条路径模式。例如，`frontend/**` 将 Vue 指南限定为前端文件。缺少路径或目录级请求不会激活文件专用规则。

跨项目、跨文件适用的知识应将这两个字段留空。全局知识一旦设置了项目或路径限制，也必须满足这些限制。

通过 API/MCP 编写知识时，全局知识省略 `stacks` 或使用空数组；技术栈专用知识在 scope 顶层使用 `"stacks": ["framework:codeigniter:4", "language:php"]`。MCP 写入工具直接接受 `stacks` 参数。

## 2. 发送声明的技术栈

Agent 应发送项目声明的完整技术栈，以及当前文件的项目相对路径：

```json
{
    "projectSlug": "my-app",
    "path": "frontend/src/App.vue",
    "stack": ["language:typescript", "framework:vue:3"]
}
```

将这些参数传给 `openkb_get_context`。路径使用正斜杠；绝对路径需要显式提供 `root`，以便安全地转换为相对路径。

对于该请求，如果没有其他作用域限制：

| 知识                     | 结果 |
| ------------------------ | ---- |
| 全局 anti-slop 规则      | 返回 |
| Vue 3 指南               | 返回 |
| TypeScript 指南          | 返回 |
| CodeIgniter 4 + PHP 指南 | 排除 |
| Vue 2 指南               | 排除 |

没有声明技术栈的请求仍可收到全局知识；技术栈专用知识需要匹配的声明。在任务文本中提到某项技术不会激活对应知识。任务文本不参与筛选或排序，也不会与知识标题、摘要或正文进行比较。

## 3. 使用可管理的技术名称

主菜单中 **Technologies（技术栈）** 页面提供数据表格和添加/编辑弹窗。管理员在此管理显示名称和别名。知识编辑器与上下文预览使用同一目录。

规范 ID 格式为 `language:<name>` 或 `framework:<name>:<major-version>`。修改显示名称不会改变规范 ID。Agent 可调用 `openkb_list_technologies` 查看名称、ID 和可用别名。

别名不区分大小写，且不能由多个技术共用。更新会在后续请求中生效，无需重启。未登记到目录的显式规范 ID 也可使用；未知的自由文本别名通过 `diagnostics.unknownStack` 报告，不会被猜测。

## 4. 获取完整结果

所有适用知识遵循相同的返回规则。默认预算约为 4,000 token，上限 12,000。预算或条目数量限制可能导致一次响应无法容纳所有全文。

- 直接阅读全文条目。对于摘要或因预算省略的条目，在依赖这些知识前，按 `requiredFetch` 中的 slug 调用 `openkb_get_knowledge` 获取全文。
- 使用相同请求携带 `nextCursor` 获取后续页面。`incompleteRequiredContext` 表示当前响应未包含所有适用知识的全文。游标失效时重新发起请求。

预算限制不会将匹配知识变为可选内容。响应会明确提供省略数量和提取/翻页指引，而不是静默丢弃知识。

## 5. 预览与排查

在 **Knowledge（知识）** 页面的 **Context preview（上下文预览）** 中输入项目、文件路径、技术栈和预算。它使用与 Agent 请求相同的检索逻辑，显示返回条目、匹配原因、全文或摘要形式以及省略诊断。

缺少预期知识时，检查激活状态、选中的技术、项目/路径限制和响应预算。空 scope 或没有 `stacks` 的 scope 表示全局知识。旧 `required`、`auto`、`manual` 返回策略不再影响筛选。

需要主动比较不同技术栈时，使用显式 `discovery: true`，或按 slug 获取已知的有效条目。关键词搜索仍由 `openkb_search` 提供，与自动上下文筛选分开。

连接方式和工具示例见 [MCP 集成](/docs/integrations/mcp)。
