# 知识生命周期

本指南解释知识如何在 OpenKB 中流动。

```text
捕获 → 版本化 → 审核 → 检索 → 记住 → 改进
  ↑                                  │
  └───────────── 提案循环 ───────────┘
```

## 1. 捕获知识

OpenKB 将每个知识条目存储为 Markdown 格式。

可通过以下方式创建或更新知识条目：

- **MCP**：Agent 搜索、检索上下文并提交持久化记忆提案
- **Web UI**：面向人类管理者的管理和审核工作流

每个知识条目包含以下字段：

| 字段 | 说明 |
| --- | --- |
| `slug` | 全局唯一标识符，例如 `backend-architecture`。 |
| `title` | 人类可读的标题。 |
| `summary` | 用于列表和检索结果的简短描述。 |
| `type` | 知识分类。 |
| `status` | `active`（有效）或 `inactive`（未激活）。 |
| `content` | 完整的 Markdown 内容。 |
| `scope` | 用于匹配项目和路径的可选匹配提示。 |
| `createdBy` | 当前版本的作者（版本 `created_by`）。 |

支持的知识类型：

- `context`
- `rule`
- `spec`
- `workflow`
- `runbook`
- `decision`
- `reference`
- `prompt`
- `skill`
- `template`

支持的状态：

- `active`：可被 MCP 搜索/上下文检索获取
- `inactive`：对 Agent 隐藏；仅保留用于历史记录/管理

只有 `active` 状态的知识条目才会用于正常的搜索/上下文检索。

人类通常在 Web 控制台创建有效知识。Agent 使用 `openkb_remember`，它会创建一个提案，而不是立即修改现有有效条目。

## 2. 知识版本化

每一次知识更新/插入都会创建一个不可变的版本。

OpenKB 在 `knowledge` 表中存储元数据，并在 `knowledge_versions` 表中存储 Markdown 快照。

当更新一个知识条目时：

1. OpenKB 写入一个新的版本行。
2. 知识条目的当前版本指针移动到新版本。
3. 旧版本继续保存，用于历史查看和恢复。

规范知识保留完整历史。在工具之间复制散乱 Markdown 则没有这一能力。

每个版本都可以包含一段简短的 **变更说明** (`changeSummary`)，解释修改了什么。在 Web 控制台的知识编辑器中，当编辑现有条目时，该字段是可选的。如果留空，OpenKB 会自动回退使用该知识的 summary。被批准的提案会使用提案的 summary 作为版本变更说明。

Web 控制台的 **知识 (Knowledge)** 列表默认显示有效条目，支持搜索、筛选、分页、Markdown 导入/导出，以及逐行的激活/未激活开关。点击条目会显示版本时间线和 **渲染 / 源码 (Rendered / Raw)** Markdown 面板。历史版本是只读快照；删除知识条目会同时删除其存储的版本历史。当保留的版本多于一个时，可以单独删除某个历史版本。

如果更新操作没有提供新的作用域 (scope) 元数据，OpenKB 会保留现有的作用域。如果提供了显式的作用域，它将替换之前的作用域。普通文本编辑不会意外扩大或缩小接收该知识的对象范围。

## 3. 审核提案变更

Agent 在工作时经常会发现缺失或过时的知识。OpenKB 支持提案优先的循环，使 Agent 可以在不静默更改单一事实来源的情况下提出持久更新建议。

```text
Agent 发现缺少知识
          ↓
Agent 创建提案
          ↓
人类审核提案
          ↓
批准 → OpenKB 写入新的知识版本
拒绝 → 规范知识保持不变
```

### 提案知识（草稿与记忆）

当没有直接写入权限的 Agent 调用 `openkb_remember` 时，OpenKB 会创建一个 **提案** (`status: open`)。人类可在 Web 控制台中审核、编辑、批准或拒绝提案。

批准是一个事务操作：只有在新知识版本写入完成后，提案才会被标记为已批准。对于新提案，批准会新建知识条目；对于更新提案，批准会增加现有条目的版本号。被拒绝的提案会保留在审核历史中，永远不会成为可检索的知识。当不存在同 slug 的其他 Open 状态提案时，被拒绝的提案可以被 **重新恢复** (`status: open`)。

在 Web 控制台中，**提案 (Proposals)** 可以按状态进行筛选（包括来自仪表盘的深层链接）。详情页面在当前有效知识旁显示提案内容（当 slug 已存在时），并提供渲染/源码 Markdown 面板、作用域展示以及批准/拒绝/恢复等操作。

## 4. 检索作用域上下文

OpenKB 可以返回针对当前项目和文件路径的相关上下文。

作用域示例：

```json
{
    "projectSlug": "openkb",
    "pathPatterns": ["backend/src/api/**", "frontend/src/views/**"]
}
```

通过 MCP 检索上下文示例：

Agent 调用 `openkb_get_context` 工具，附带 `path="backend/src/api/app.ts"`。

OpenKB 过滤掉未激活的知识条目，检查作用域，然后对更具体的匹配赋予更高排序权重。当当前路径为 `backend/src/api/app.ts` 时，作用域限定为 `backend/src/api/**` 的知识条目会优于宽泛的通用笔记。

## 5. 未激活知识

知识可以随时从 Web 控制台编辑器中取消激活，而不会丢失其历史记录。

- **`status: inactive`**：保存在数据库历史中，在 Web UI 中可见，但在检索过程中跳过。
- **`status: active`**：包含在向量上下文查找、关键字搜索和列表工具中。

MCP 搜索与上下文检索会跳过未激活条目。需要检查、还原或管理未激活知识时，请使用 Web 控制台。

## 6. 记住变更内容

Agent 完成工作后，应该提交未来会话需要了解的持久化知识。MCP 优先的路径是：

1. 工作前调用 `openkb_get_context`
2. 执行任务
3. 对持久性发现调用 `openkb_remember`
4. 人类在 Web UI 中批准有用的提案

这条路径替代了旧的静态导出优先工作流。OpenKB 作为 AI 记忆层运行，而不是以生成特定编辑器文件为主要职责。

## 7. 改进知识库

随着 Agent 和人类的持续工作，循环不断运转：

- 在进行非平凡更改前搜索 OpenKB
- 为当前路径检索限定作用域的上下文
- 提出缺失或修正的知识
- 批准有用的提案，以便未来的 Agent 可以检索它们

项目知识保持更新，Agent 只加载需要的条目。
